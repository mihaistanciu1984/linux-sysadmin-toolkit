# NVIDIA Mellanox SN2100 Initial Setup

This procedure describes the basic preparation of an NVIDIA Mellanox SN2100 switch running Cumulus Linux with NVUE.

> This procedure uses the NVUE command line and is intended for Cumulus Linux 5.15 or later.

## Requirements

- NVIDIA Mellanox SN2100 switch
- Serial console access
- Management network connection
- Management IP address, gateway, DNS and NTP information
- Administrative access

Example values used in this procedure:

| Setting | Example |
|---|---|
| Hostname | `mellanox-sn2100-01` |
| Management IP | `192.0.2.10/24` |
| Gateway | `192.0.2.1` |
| DNS server | `192.0.2.53` |
| NTP server | `time.example.com` |

Replace these values with the settings assigned to your environment.

## 1. Connect through the serial console

Use the serial console for the initial configuration.

Changing the management IP address through an SSH session can disconnect the current session.

## 2. Check the switch and operating system

```bash
nv show system
cat /etc/os-release
sudo decode-syseeprom
nv show system health
```

These commands display:

- Cumulus Linux version
- Switch model
- Serial number
- Hardware and power supply health

## 3. Change the default password

Change the password of the current administrative user:

```bash
passwd
```

Use a strong password and store it in an approved password manager.

## 4. Configure the hostname

```bash
nv set system hostname mellanox-sn2100-01
```

Do not use spaces or underscores in the hostname.

## 5. Configure the management interface

Configure a static address on the dedicated `eth0` management interface:

```bash
nv set interface eth0 ipv4 address 192.0.2.10/24
nv set interface eth0 ipv4 gateway 192.0.2.1
```

## 6. Configure DNS

For Cumulus Linux 5.15 or later:

```bash
nv set system dns server 192.0.2.53
```

The DNS and NTP command syntax is different in Cumulus Linux 5.14 and earlier. Always check the installed version before applying these commands.

## 7. Configure the time zone and NTP

```bash
nv set system date-time timezone Europe/Bucharest
nv set system ntp server time.example.com iburst enabled
```

Correct time synchronization is important for logs, monitoring and authentication.

## 8. Review and apply the configuration

Review the pending changes:

```bash
nv config diff
```

Apply the configuration:

```bash
nv config apply
```

Save it explicitly as the startup configuration:

```bash
nv config save
```

The persistent NVUE configuration is stored in:

```text
/etc/nvue.d/startup.yaml
```

Do not edit this file manually when managing the switch with NVUE.

## 9. Verify the configuration

Check the hostname:

```bash
hostnamectl
```

Check the management interface:

```bash
nv show interface eth0
ip -br address show eth0
ip route
```

Test the gateway:

```bash
ping -c 3 192.0.2.1
```

Test DNS:

```bash
getent hosts example.com
```

Check time synchronization:

```bash
timedatectl
```

Check hardware status:

```bash
nv show system health
```

Check connected network devices:

```bash
sudo lldpcli show neighbors
```

## 10. Create a configuration backup

Display the applied configuration:

```bash
nv config show
```

Export it to a local file:

```bash
nv config show > ~/mellanox-sn2100-01-nvue-backup.yaml
```

Copy the backup to an administration computer or configuration repository.

## Initial deployment checklist

Before connecting the switch to production, verify:

- The default password was changed.
- The hostname is correct.
- The management IP address is reachable.
- The default gateway is correct.
- DNS resolution works.
- NTP synchronization works.
- Power supplies and fans report a healthy status.
- Connected devices appear through LLDP.
- The configuration was saved and backed up.

## Important notes

Do not mix NVUE commands with direct changes to Linux configuration files.

Do not manually append configuration to `/etc/nvue.d/startup.yaml`.

Do not use the legacy `net add` commands unless the switch runs an older Cumulus Linux release that uses NCLU.

Review the running Cumulus Linux version before copying commands from documentation for another release.
